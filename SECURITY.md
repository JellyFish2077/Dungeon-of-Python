# Безопасность: что реально защищено, а что нет

Документ нужен, чтобы не выдавать ограничения за гарантии. Здесь написано
ровно то, что делает сервер, и то, что он не делает.

## Модель угроз

Сервер запускается на ноутбуке преподавателя в локальной сети академии.
Ученики считаются доверенными, но любопытными: приложение само учит
файловому вводу, `subprocess` и модулям, поэтому вопрос «а что будет, если
ученик выполнит `open('..\\..\\.secret')`» — не теоретический.

## Песочница кода: два режима

### WSL (по умолчанию, если установлен)

На Windows код ученика запускается через WSL в отдельных user/mount/pid/net
namespaces (`unshare -Urmpf -n`). Внутри видны только:

- каталог задачи, примонтированный bind-mount;
- системный Python и стандартная библиотека;
- пустые заглушки вместо `/mnt`, `/home`, `/tmp` и `/root`.

`/mnt` с проектом, `.secret` и `.admin-secret` закрывается tmpfs, сеть
выключена, число процессов, память, CPU и размер файла ограничены. Даже
цепочка классов, дающая `os`, не выходит за пределы этих namespaces.

Проверить режим:

```bash
# в консоли сервера при старте:
#   Изоляция кода: WSL (отдельные mount/pid/net namespaces, /mnt скрыт)
```

Принудительно:

```bash
set PYQUIZ_SANDBOX=wsl      # Windows cmd
$env:PYQUIZ_SANDBOX="wsl"   # PowerShell
```

Если `PYQUIZ_SANDBOX=wsl`, а WSL недоступен, проверка кода не работает
(fail closed), а не откатывается молча в небезопасный режим.

### process (запасной, без изоляции ОС)

Если WSL не установлен и режим `auto`, код выполняется обычным процессом
Python с правами пользователя сервера. Белый список `__builtins__` и модулей
остаётся, но границей безопасности он не является: обход через
`().__class__.__bases__[0].__subclasses__()` и подобные цепочки возможен.
В этом режиме секреты проекта **не защищены**. Для занятия без WSL
используйте `--no-code`.

## Что защищено и в режиме process

| Что | Как |
|---|---|
| Запись `users.json`, `results.json`, `server.py` | Код может писать только в каталог задачи; `open` с `w`, `a`, `x`, `+` запрещён |
| Глобалы сервера | Код выполняется через `exec` в отдельном пространстве имён, а не в глобалах прелюдии |
| Переменные окружения | Процесс получает пустое окружение, кроме `SYSTEMROOT`/`TEMP` на Windows |
| Встроенные функции | `eval`, `exec`, `compile`, `globals`, `getattr`, `input`, `open` заменены или отсутствуют |
| Импорты | Белый список чистых модулей; `os`, `sys`, `subprocess`, `socket`, `ctypes` не импортируются |
| Ресурсы | 5 секунд, 512 МБ, 2 МБ на файл, 64 КБ на stdout/stderr |
| `/api/submit` | Итог похода только с токеном; проверяются инварианты процента и размеры файла результатов |
| `/api/check` | Тесты берутся из серверного банка по `taskId`; клиентские тесты игнорируются; сравнение каноническое, без `__eq__` ученика |
| `?debug=1` | Открывает состояние игры только вместе с `--dev` |

## Чего защита НЕ даёт

1. **Без WSL изоляции ОС нет.** Код исполняется обычным Python-процессом с
   правами пользователя, от имени которого запущен сервер. Настоящая защита
   требует WSL, отдельного низкопривилегированного пользователя, AppContainer
   или контейнера — это настройка компьютера, а не строчка в коде.

2. **Цепочка классов остаётся.** Даже с белым `__builtins__` путь
   `().__class__.__bases__[0].__subclasses__()` ведёт к настоящим встроенным
   функциям. В WSL он ограничен namespaces и каталогом задачи; в режиме
   process — это полный выход к файлам пользователя.

3. **Задания генератора на код временно не проверяются.** Их тесты рождаются
   на клиенте, поэтому `/api/check` отвечает `staleTask`, а игра не выдаёт
   такие задания. Банк `code-tasks.js` (11 заданий) проверяется сервером.

4. **Данные, которые сервер отдаёт по сети, не защищены шифрованием.** Это
   обычный HTTP в локалке: трафик виден соседям. Пароли передаются открытым
   текстом при входе.

5. **WSL — не отдельная машина.** Код видит системный Python и `/usr`; он не
   должен использоваться как замена изоляции для недоверенного кода в
   интернете. Для урока этого достаточно, для публичного сервера — нет.

## Что делать, если риск неприемлем

По убыванию простоты:

1. Установить WSL2 и оставить `PYQUIZ_SANDBOX=auto` (или `wsl`).
2. Запускать сервер с ключом `--no-code`. Код не выполняется вообще, риск
   исчезает полностью. Теряется только один тип заданий в подземелье.
3. Запускать сервер из обычного пользовательского аккаунта, не от админа, и
   держать папку проекта на диске, который ученику не нужен.
4. Для доверенной сети: снимок перед занятием (`_backup/`) делает откат
   однострочной командой, а `run_all_checks.py` и pre-commit hook не дают
   сломанной защите уехать в коммит.

## Публичная веб-сборка

В `public/` (Itch.io) сервера нет: код ученика исполняется Pyodide в Web
Worker внутри браузера. Это безопаснее для компьютера игрока — у кода нет
доступа к файлам и сети за пределами браузерной песочницы, — но это
**однопользовательская** версия: результаты, профиль и проверки локальные,
их можно подменить через инструменты разработчика. Для рейтинга, класса или
любых соревнований нужна серверная проверка.

Проверка кода в веб-сборке использует тот же банк тестов, но не скрывает их
от игрока: тесты уже лежат в `static/code-tasks.js`. Это осознанный компромисс
для одиночной игры; в серверной версии тесты приходят по `taskId`.

## Как проверить, что защита на месте

```bash
python verify_server.py
```

Раздел «песочница» закрывает 22 способа выхода наружу, включая четыре
реальных payload'а из адверсариального ревью, и отдельно проверяет, что
обычные задания (функции, `import math`, `import random`, классы, генераторы
списков, `try/except`) продолжают выполняться.

- В WSL все 22 зелёные.
- При `PYQUIZ_SANDBOX=process` четыре payload'а красные — это и есть
  доказательство, что проверка не декоративная.

Ручная проверка на живом сервере:

```bash
curl -s -X POST http://127.0.0.1:8000/api/check \
  -H 'Content-Type: application/json' \
  -d '{"code":"open(\"../.secret\").read()","taskId":"attack_power"}'
# {"ok": false, "error": "PermissionError: Доступ к файлам вне папки задачи запрещён", ...}
```

Проверка задания банка:

```bash
curl -s -X POST http://127.0.0.1:8000/api/check \
  -H 'Content-Type: application/json' \
  -d '{"code":"def attack_power(base, bonus):\n    return base + bonus","taskId":"attack_power"}'
# {"ok": true, "passed": 3, "total": 3, ...}
```
