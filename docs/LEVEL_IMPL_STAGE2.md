# Этап 2: содержимое по ролям комнат

Статус: реализовано. Генератор v2 включён (`GEN_V2 = true`),
кампания 15 этажей пока за флагом (`CAMPAIGN_V2 = false`).

## 1. Цель

Убрать случайную раскладку врагов, лута, ловушек и костров по свободным
клеткам. Комната получает роль в плане, и содержимое ставится по этой
роли. Старый путь остаётся для legacy-этажей, арен и бесконечного спуска.

## 2. Роль → содержимое

| Роль | Содержимое |
|---|---|
| `entry` | Вход, лестница наверх. Без врагов и ловушек. |
| `junction` | Развилка. Безопасный проход. |
| `combat` | 1–2 группы врагов. При нехватке комнат сюда же идут лишние группы. |
| `gate` | Страж лестницы. |
| `crossing` | Переправа; ловушки и среда — этап 3. |
| `hazard_hall` | Группа врагов и опасный зал; плотная среда — этап 3. |
| `treasure` | 2–3 сундука, 1 ловушка. |
| `vault` | Запертая комната: 2 предмета, 2 жилы, дверь с ключом/рычагом. |
| `resource` | 2–3 жилы. |
| `rest` | Костёр. |
| `lore` | Табличка; иногда сундук. |
| `ambush` | Отряд 2–3, ловушка. |
| `elite` | Элита + обычный враг. |
| `secret` | Редкий сундук. |

## 3. Новые поля этажа

В `BIOMES_V2` у обычных этажей добавлены:

```js
{
  traps: 3,          // ловушек на этаж
  chests: 2,         // сундуков на этаж, без тайника
  squadChance: 0.10  // шанс, что группа выйдет отрядом 2–3
}
```

Для v1 эти поля не заданы: работают старые формулы и `trapBudgetForFloor`.

## 4. Алгоритм

### 4.1. Враги

1. `elite`-комнаты дают группу из элиты и обычного.
2. `ambush` — отряд 2–3.
3. `hazard_hall` и `combat` — по одной группе.
4. Если групп меньше `f.count`, остаток добавляется в `combat`/`hazard_hall`
   до трёх групп на комнату.
5. Группа ставится в клетки комнаты; участники ищут соседнюю свободную
   клетку внутри той же комнаты.
6. Страж ставится у лестницы в `gate`.

### 4.2. Лут и интерактив

- Сундуки — в `treasure`, редкий — в `secret`.
- Жилы — в `resource`, две — внутри `vault`.
- Костры — только в `rest`.
- Таблички — в `lore`.
- Рычаг — в `lore`/`junction`, не ближе 4 клеток к двери тайника.
- Торговец — только на первом этаже биома (кроме самого первого этажа
  игры), в комнате входа. Один на биом; ассортимент фиксируется и не
  обновляется при спуске.
- Тайник использует готовую комнату `vault`: её выход становится
  запертой дверью, остальные выходы запечатываются.

### 4.3. Ловушки

- Бюджет — `f.traps` для v2, иначе `trapBudgetForFloor`.
- Сначала `treasure`, `ambush`, `hazard_hall`, `crossing`, затем `combat`.
- Не ближе 3 клеток от входа.
- Резерв — только коридоры или риск-комнаты.

## 5. Совместимость

- Legacy-этажи, арены и бесконечный спуск идут старым путём.
- `state.plan` остаётся транзиентным: в сохранение не попадает.
- Новые поля `camps`, `traps`, `chests` сериализуются существующим кодом.
- `GEN_V2` можно выключить через `setGenV2(false)` или `?gen=legacy` в dev.

## 6. Проверки

- 1500 карт v1/v2 проходят `genValidatePlan`.
- На 50 этажах v2 проверено:
  - враги стоят в `combat`/`ambush`/`elite`/`hazard_hall`;
  - страж — в `gate`;
  - костры — в `rest`;
  - сундуки — в `treasure`/`secret`/`vault`;
  - жилы — в `resource`/`vault`;
  - таблички — в `lore`;
  - рычаг — в `lore`/`junction`;
  - дверь тайника — в `vault`.
- `python run_all_checks.py --quick` — зелёный.

## 8. Автоматический плейтест

Бот `play_dungeon.js`, кампания из нескольких походов одним героем:

| Сложность | Верных | Походов | Побед | Итог |
|---|---:|---:|---:|---|
| Лёгкая | 75% | 3 | 3 | 0 смертей |
| Обычная | 85% | 1 | 1 | 39 верных / 3 неверных |
| Обычная | 75% | 3 | 2 | 1 обрыв по лимиту ходов |
| Сложная | 75% | 3 | 2 | 1 смерть на 9 этаже |
| Обычная | 60% | 2 | 0 | дошли до 6 этажа, 1 затвор |

Исключений и падений игры нет. Это проверка проходимости, а не
субъективной оценки карт.

## 9. Открытые вопросы

1. Арены 15-этажной кампании пока используют старую раскладку: в них
   могут появляться костры и ловушки. Это этап 4.
2. Плотность групп на 50×32: до трёх групп в одной `combat`-комнате.
   После ручного плейтеста можно ограничить двумя.
3. Сундуки `vault` считаются отдельно от `f.chests`; при желании
   свести в один бюджет.
4. Бот на обычной сложности один раз упёрся в лимит ходов на 4 этаже;
   отдельный повтор того же сида прошёл дальше. Нужен ручной тест
   маршрута, если повторится.
