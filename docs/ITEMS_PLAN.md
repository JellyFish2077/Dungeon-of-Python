## 2. Правила названий

- ID не меняем: `id` — ключ сохранений, кодекса и спрайтов.
- Меняем только `name` и, при необходимости, `desc`.
- Тир 0–1: простое и понятное название. Игрок должен понимать вещь
  без легенды.
- Тир 2–3: название с материалом или ролью: «Пепельный клинок»,
  «Панцирь стража».
- Тир 4: короткое эпическое имя: «Эгида», «Корона тронного зала».
- Одно название — один образ. Не повторяем «клинок» дважды в одном
  слоте без причины.
- Длина: до 24 символов, чтобы влезало в сумку и лавку.

## 3. Бюджет характеристик

Ориентир, чтобы новые вещи не ломали кривую:

| Тир | Оружие, атака | Броня, HP / защита | Амулет |
|---|---|---|---|
| 0 | 3 | 10 / 0 | — |
| 1 | 5–6 | 20 / 1 | 3–4 одного стата |
| 2 | 7–11 | 22–35 / 1–3 | 1–2 двух статов + эффект |
| 3 | 13–16 | 30–55 / 3–6 | 3–6 + HP 20–25 + эффект |
| 4 | 18–20 | 75–85 / 9–10 | 7–8 + HP 40–50 + эффект |

Эффект — это торговля: вещь с сильным эффектом может иметь на 1–3
очка меньше сырых статов. Комплектные вещи могут быть слабее
одиночных, потому что добирают бонус семьи.

Что проверить отдельно:

- `trident_precise` (11 атаки + 20% крита) сильнее `steel_sword`
  (10 атаки) вне комплектов — это нормально, пока они в разных семьях.
- `vampiric_blade` + `blood` дают 50% вампиризма; нужен потолок или
  проверка, что это не бесконечное лечение.
- `luck` + `ledger_amulet` дают 70% золота; `crown` — ещё 50%,
  но её нельзя надеть вместе с амулетом удачи. Проверить экономику
  предельной сборки.
- `equippedEffect` складывает только первый эффект. Исправить до
  добавления вещей с критом/вампиризмом в разных слотах.

## 5. Aseprite

Новые спрайты — отдельный файл:

```text
tools/art/aseprite/items3.aseprite
```

Правила:

- канвас 32×32, RGBA, слой `art`, без фона;
- один кадр = один тег, имя тега = ID предмета;
- палитра `tools/art/palette.gpl`;
- 8–12 цветов, контур 1 px `#05070d`;
- предмет читается на 25×25 px, не выходит за 32×32;
- оружие — диагональ, броня — плечи и вырез, амулет — крупный
  центральный камень, зелье — круглая колба.

Краткие задания:

| ID | Силуэт |
|---|---|
| `ash_blade` | Тёмный клинок по диагонали, оранжевые трещины-угольки, обгоревшая рукоять |
| `ash_mantle` | Тёмная мантия с капюшоном, угольные плечи, оранжевая кромка |
| `ash_eye` | Круглый обсидиановый амулет, оранжевый вертикальный зрачок |
| `dawn_blade` | Светлый клинок, золотое навершие-солнце, синяя рукоять |
| `warden_plate` | Тяжёлые латы, тёмная сталь, красная накидка, шипы на плечах |
| `heart_abyss` | Тёмный камень-сердце, красное свечение, серебряная цепь |

После рисования:

```powershell
python tools/art/export_aseprite.py
python tools/art/build_art.py
python tools/art/export_aseprite.py --check
python tools/art/build_art.py --check
```

`items3` нужно добавить в `FAMILIES` в `tools/art/export_aseprite.py`
(семейство `items`) и в список `custom_slice.assets` в `art.json`.

## 6. Вещи на герое

Базовый герой в подземелье — отдельный спрайт `player_base`: белая
майка, коричневые штаны, пустые руки. Меню и портреты по-прежнему
используют старый `player`.

Надетые вещи рисуются слоями поверх базы:

| Слой | Что показывает | z-index |
|---|---|---|
| `player-armor` | броня, роба, щит | 2 |
| `player-amulet` | амулет на цепи | 3 |
| `player-crown` | корона на голове | 3 |
| `player-ring` | перстень на левой руке | 3 |
| `player-weapon` | оружие в правой руке | 4 |

Исходник — `tools/art/aseprite/equipment.aseprite`: 29 кадров, по
одному тегу на каждый надеваемый предмет. Слои нарисованы по той же
сетке 32×32, что и `player_base`, поэтому в CSS они занимают ровно
клетку героя (`inset: 0; width/height: 100%`) и не требуют подгонки
координат. Цвета взяты из `palette.gpl`, у каждой вещи свой вариант.

Сборка:

```text
tools/art/aseprite/equipment.aseprite
  → tools/art/src_custom/equipment/<id>.png
  → WORN_SPRITES в static/sprites.js
  → playerEquipmentLayers() в static/game.js
```

Если у вещи нет слоя, `playerEquipmentLayers()` откатывается к
иконке из `ITEM_SPRITES`; `build_art.py` заранее проверяет, что слой
есть у каждого предмета с slot `weapon`, `armor` или `accessory`.
Зелья не надеваются и слоя не имеют.

## 7. Порядок внедрения

1. Утвердить названия и первую партию.
2. Нарисовать шесть спрайтов в `items3.aseprite`.
3. Добавить записи в `ITEM_POOL` и `ITEM_SETS` в `static/items.js`.
4. Прогнать `export_aseprite.py`, `build_art.py` и проверки.
5. Отдельным шагом исправить стакинг эффектов и сравнение в сумке.
6. После этого — баланс предельных сборок и, при необходимости,
   ещё одна партия предметов.

## 8. Решено

1. ID предметов не меняем; переименование затрагивает только `name`.
2. Первая партия — шесть вещей: комплект «Пепел» и три вещи тира 4.
3. Новые спрайты рисуются в отдельном `items3.aseprite`.
4. Порядок: сначала спрайты, потом записи в `items.js`.
5. Герой подземелья — `player_base`; надетые вещи — отдельные слои
   из `equipment.aseprite`, а не иконки предметов поверх спрайта.
