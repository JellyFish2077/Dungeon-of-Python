## Срочное

1. **Без изоляции ОС код ученика не запускать.** На Windows нужен WSL:
   при `PYQUIZ_SANDBOX=auto` сервер сам выберет namespaces, если WSL есть.
   Если WSL нет — сервер предупреждает при старте; на занятии используйте
   `--no-code`.
2. Не запускать `verify_admin.py` на рабочей папке без нужды: он теперь
   изолирован (`tempfile` + `PYQUIZ_NO_BACKUP=1`), но пусть так и остаётся.
3. `pre-commit` гоняет `run_all_checks.py --quick` (check, server, admin).
   Полный набор с node — перед занятием/релизом.

## Команды

```
python server.py --local             # только этот компьютер
python server.py --local --dev       # панель разработчика, F2
python server.py --no-code           # без выполнения кода учеников

python run_all_checks.py             # всё, включая node
python run_all_checks.py --quick     # без node
python run_all_checks.py --only verify_server check
python verify_dungeon.py             # подземелье; при сбое код 1
node play_dungeon.js --games=20      # бот проходит подземелье

python launch_game.py                # классная версия + браузер
python launch_standalone.py          # standalone + полноэкранный браузер
python tools/build_web.py            # собрать standalone/build/
python tools/fetch_pyodide.py        # локальный Pyodide (офлайн)
python tools/package_web.py          # dist/pydungeon-standalone-<версия>.zip
```

`?debug=1` открывает `window.__pyquiz`, `__setFloor`, `__validateFloor`,
`__buildFloor` — только при запуске с `--dev`.

## Что сделано в 1.6.1

- **Главное меню:** шесть пунктов одним списком — «Новая игра», «Загрузить»,
  «Настройки», «Профиль», «Об игре», «Выход». Шестерёнка и нижняя строка
  аккаунта убраны; «Загрузить» недоступна без сейва, «Об игре» — отдельный
  экран. «Новая игра» приводит в деревню, окно стража открывается только по E
  у входа. В веб-сборке «Выход» ведёт на страницу завершения, а не обратно в меню.
- **Пауза:** ESC и кнопка «Пауза» в шапке открывают отдельное меню —
  «Продолжить», «Сохранить», «Загрузить», «Настройки», «Выход в Меню».
  Прямого «Выйти» в шапке нет: в меню можно вернуться только через паузу.
- **Живой фон меню:** процедурные подземелья без тумана войны, два слоя
  плавно сменяются каждые 8 секунд; в паузе фон скрыт. Генератор —
  `static/menu-bg.js`, canvas 960×600.
- **Меню слева:** главное меню и пауза прижаты к левому краю; подписи справа
  у кнопок скрыты, остались только названия; логотип Py, слоган под заголовком
  и подсказка управления внизу убраны.
- **Сохранение деревни:** «Сохранить» в паузе пишет позицию героя и в деревне,
  «Загрузить» возвращает к ней; профиль и постройки остаются в профиле.
  Переименование переносит и снимок деревни (`pyquiz_village_v1`).
- **Меню сохранений:** «Сохранить»/«Загрузить» открывают три ячейки. Пустая
  пишет новое сохранение; у записанной справа — скриншот, описание и кнопки
  «Перезаписать», «Переименовать», «Удалить» (и «Загрузить» в режиме загрузки).
  Старый одиночный сейв переезжает в первую ячейку.
- **P2 из ревью:** чекбокс «меньше анимации» синхронизируется после reload;
  корень веб-сборки сразу открывает главное меню, имя меняется в профиле;
  мобильные «Назад» — 44 px; «Выход» без похода уходит сразу, а текст confirm
  говорит «стартовый экран»; Esc закрывает меню и для гостя.
- **Флак `verify_dungeon`:** проверки тайника убирают все объекты с клетки
  перед дверью и требуют `kind === "vault"`; ледяная проверка принимает лишнее
  действие монстра — шаг или атаку. Сундук/рычаг/табличка и атака вместо шага
  больше не дают ложный сбой.
- **Публикация:** статическая сборка публикуется из `gh-pages`; workflow
  `.github/workflows/pages.yml` остаётся в истории. Для VPS —
  `deploy/pyquiz.service`, `deploy/Caddyfile`, `deploy/pyquiz.env.example`.
  Смоук-сервер `verify_web.py` держит очередь 128 соединений, поэтому Chromium
  не получает `ERR_CONNECTION_REFUSED`. `build_web.py` добавляет к JS/CSS
  `?v=<время сборки>`, чтобы GitHub Pages не отдавал старый `game.js`.
- **Итог похода:** на смерти и победе общий блок — этаж, золото за поход и в
  банке, монстры, ответы, код, повторение; подсказка следующего шага. Проверки
  в `tools/checks.js`.
- Проверки: полный прогон 7/7, `verify_server` 85/85, `verify_web` 48/48.

## Что сделано в 1.6.0

- **Классическое главное меню.** Крупное название и один вертикальный список
  действий: «Начать поход» / «Продолжить поход» / «Вернуться в игру»,
  «В деревню», «Выход»; «Новая игра» появляется, когда поход уже идёт.
  Стрелки ↑↓ выбирают, Enter подтверждает. Меню одно для классной и
  веб-сборки; различается только вход (PIN или локальное имя). Кнопка «Меню»
  в шапке открывает его в игре.
- **Шестерёнка настроек.** Отдельная кнопка в правом верхнем углу, а не пункт
  списка. Открывает экран: звук и громкость (синтезированные эффекты без
  файлов), полный экран, «меньше анимации», сброс подсказок и памятка по
  управлению. Хранятся в `pyquiz_settings_v1`. Аккаунт — строка игрока внизу:
  вход, регистрация, смена.
- **Действия и фокус.** «Начать поход» открывает окно стража, «Продолжить
  поход» поднимает сейв, «В деревню» сохраняет или закрывает меню, «Выход»
  сохраняет и уводит на главную. После «Начать поход» фокус в окне стража,
  Tab не уходит в шапку; при Tab по шестерёнке/аккаунту золотая строка списка
  снимается.
- **Переименование в веб-сборке.** «Изменить имя» переносит профиль, ключ
  сейва, имя владельца внутри сейва и метку места; занятое имя не затирается.
- **Звук.** Верный и неверный ответ, победа и поражение; аудиоконтекст
  создаётся по первому действию игрока.
- **Под меню игра не идёт.** Клавиши, E и пропуск хода не срабатывают, пока
  открыт стартовый экран; подсказка управления веб-сборки под меню скрыта.
- **Исправлен вход и регистрация.** `applyServerProfile` объявляла
  `const merged` и переприсваивала её ниже: после создания сессии вход падал
  с «Сервер недоступен». Теперь профиль применяется, страница перезагружается.
- Проверки: `verify_web` — 16/16 в Edge, `verify_server` — 85/85,
  `verify_dungeon` — проверки серверной копии профиля и переноса сейва при
  переименовании.

## Что сделано в 1.5.0

- **Калибровка перед первым спуском.** Шесть вопросов из общего банка, по два
  уровня 1–3. Уровень 1–3 хранится в `profile.knowledge`, синхронизируется с
  сервером, переезжает между компьютерами; у стража можно пройти заново или
  пропустить (тогда базовый уровень).
- **Выдача с поправкой.** `floorLevels()` сдвигает вопросы и задания на
  ступень вниз/вверх (`knowledgeOffset`), не трогая силу монстров.
- **Учительская таблица.** `/results`: новая колонка «Старт», прежняя
  «Уровень» переименована в «Итог». `knowledgeLevel` проходит через
  `/api/submit` и `clean_result`.
- **Сервер.** `clean_profile` принимает `knowledge` по белому списку:
  уровень 0–3, 6 ответов, 12 баллов; старые профили получают 0.
- Проверки: 85 в `verify_server`, 966+ в `verify_dungeon`; полный прогон 7/7.
